## 8.1 Memory Hierarchy and Address Binding
In modern computer architectures, the CPU can access only two storage entities directly: main memory (RAM) and registers. Any CPU instructions in execution and data being referenced must reside in one of these physical devices. If data is not in memory, it must be transferred from secondary storage (e.g., NVMe SSD or HDD) via the system bus before execution.

Address binding occurs in three distinct phases:
1. Compile Time: If it is known at compile time where the process will reside in physical memory, absolute code can be generated.
2. Load Time: If memory location is not known at compile time, relocatable code is generated.
3. Execution Time (Dynamic Binding): If the process can be moved during its execution from one memory segment to another, binding is delayed until runtime. This requires special hardware support: the Memory Management Unit (MMU).

## 8.2 Paging Mechanics & Logical-to-Physical Address Translation
Paging is a memory management scheme that eliminates the need for contiguous allocation of physical memory.
- Logical Address Space is divided into fixed-size blocks called Pages.
- Physical Memory is partitioned into fixed-size blocks called Frames (or Page Frames).
The size of a page is typically a power of 2, varying between 4 KB ($2^{12}$ bytes) and 64 KB ($2^{16}$ bytes).

Address Translation Formula:
A logical address generated by the CPU consists of two components:
$$\text{Logical Address} = (p, d)$$
Where:
- $p$ is the Page Number (used as an index into the process Page Table).
- $d$ is the Page Offset (displacement within the page).

If the total logical address space is $2^m$ bytes and page size is $2^n$ bytes, then the high-order $m - n$ bits designate the page number $p$, and the low-order $n$ bits designate the page offset $d$.

$$\text{Physical Address} = (f \times 2^n) + d$$
Where $f$ is the Frame Number retrieved from the page table entry $\text{PTE}[p]$.

## 8.3 Translation Lookaside Buffer (TLB) and Effective Memory Access Time (EMAT)
Standard two-level paging requires two memory accesses per logical reference:
1. One access to read the Page Table Entry (PTE) from RAM.
2. One access to retrieve the actual physical data byte.

To mitigate this 100% memory access penalty, modern CPUs employ a fast hardware associative cache called the Translation Lookaside Buffer (TLB).
When a logical address is presented:
1. The CPU searches the TLB associatively for page number $p$.
2. If $p$ is found (TLB Hit), the frame number $f$ is retrieved in $\approx 1 \text{ ns}$.
3. If $p$ is not found (TLB Miss), a memory reference to the page table in RAM is required ($\approx 100 \text{ ns}$), and the resulting mapping is cached in the TLB.

Effective Memory Access Time (EMAT) Formula:
Let $\alpha$ be the TLB Hit Ratio ($0 \le \alpha \le 1$), $\epsilon$ be the TLB lookup time, and $M$ be the main memory access time.
$$\text{EMAT} = (\epsilon + M) \cdot \alpha + (\epsilon + 2M) \cdot (1 - \alpha)$$
Simplifying:
$$\text{EMAT} = \epsilon + M + M \cdot (1 - \alpha)$$

Example Problem:
Given $\alpha = 80\% = 0.8$, $\epsilon = 20 \text{ ns}$, and $M = 100 \text{ ns}$:
$$\text{EMAT} = 20 + 100 + 100 \cdot (1 - 0.8) = 120 + 20 = 140 \text{ ns}$$

# Chapter 9: Virtual Memory & Page Replacement

## 9.1 Virtual Memory Concept and Demand Paging
Virtual memory is a technique that allows the execution of processes that are not completely in physical memory. It decouples the user logical memory from physical memory, allowing an arbitrarily large virtual address space (e.g., 64-bit address space $\approx 16 \text{ Exabytes}$) on machines with modest physical RAM.

Demand Paging loads pages into memory only when they are referenced during execution (lazy swapper).
When a process references an unmapped or non-resident page, the hardware encounters an invalid bit in the page table, triggering a Page Fault Interrupt to the OS kernel.

The 6-Step Page Fault Handling Routine:
1. The CPU checks an internal state table to determine if the reference was valid or invalid.
2. If invalid, the process is terminated (Segmentation Fault). If valid but page is not in RAM, the OS initiates a page fault trap.
3. The OS finds an available free frame from the free-frame pool.
4. The OS schedules a disk I/O operation to read the requested page from swap space into the assigned physical frame.
5. Once disk transfer completes, the page table entry is updated (valid bit set to 1, frame number recorded).
6. The CPU restarts the instruction that was interrupted by the page fault.

## 9.2 Page Replacement Algorithms
When memory is fully allocated and a page fault occurs, the OS must select a victim page to swap out to disk.

1. First-In, First-Out (FIFO): Replaces the oldest page in memory. Suffers from Belady's Anomaly (allocating more physical frames can paradoxically increase the number of page faults).
2. Optimal (OPT) Algorithm: Replaces the page that will not be used for the longest period in future. Produces the theoretical lowest possible page fault rate, but is impossible to implement in practice without future knowledge. Used as a benchmark.
3. Least Recently Used (LRU): Replaces the page that has not been referenced for the longest period of time. Approximates OPT by using recent past as a proxy for the future. Implemented via hardware counter or doubly-linked stack.

## 9.3 Thrashing and Working-Set Model
Thrashing occurs when a computer's virtual memory subsystem is in a constant state of paging, rapidly swapping pages in and out of swap space, leading to a near-total collapse of CPU utilization.

Causes of Thrashing:
If the sum of the locality sizes of all active processes exceeds total physical memory:
$$\sum_{i} \text{Locality}_i > \text{Total Physical Frames}$$
Processes spend more time waiting for the paging I/O device than executing user code.

The Working-Set Model:
Proposed by Peter Denning, the working set parameter $\Delta$ defines the working-set window (a fixed number of page references).
The working set of process $P_i$, denoted $WSS_i$, is the set of pages referenced in the most recent $\Delta$ page references.
Total demand for frames $D$:
$$D = \sum_{i} WSS_i$$
- If $D \le \text{Available Frames}$, the system operates with high throughput.
- If $D > \text{Available Frames}$, the OS must suspend one or more processes (medium-term scheduler swap out) to prevent thrashing.

# Chapter 7: Deadlocks & Synchronization

## 7.1 Necessary Conditions for Deadlock (Coffman Conditions)
A deadlock is a situation wherein two or more processes are permanently blocked because each process holds a resource while waiting for another resource held by another process.

A deadlock can arise if and only if all four Coffman conditions hold simultaneously in a system:
1. Mutual Exclusion: At least one resource must be held in a non-shareable mode (only one process can use it at any given instant).
2. Hold and Wait: A process must be currently holding at least one resource and actively waiting to acquire additional resources held by other processes.
3. No Preemption: Resources cannot be forcibly confiscated from a process; a resource can be released only voluntarily by the process holding it after completing its task.
4. Circular Wait: A closed chain of processes $\{P_0, P_1, \dots, P_n\}$ exists such that $P_0$ is waiting for a resource held by $P_1$, $P_1$ is waiting for $P_2$, and $P_n$ is waiting for a resource held by $P_0$.

## 7.2 Banker's Algorithm for Deadlock Avoidance
Developed by Edsger Dijkstra, the Banker's Algorithm avoids deadlocks by ensuring the system never enters an Unsafe State.

Data Structures for $n$ processes and $m$ resource types:
- $\text{Available}[m]$: Vector of length $m$. If $\text{Available}[j] = k$, then $k$ instances of resource type $R_j$ are free.
- $\text{Max}[n][m]$: $n \times m$ matrix defining maximum demand of each process.
- $\text{Allocation}[n][m]$: $n \times m$ matrix defining resources currently allocated to each process.
- $\text{Need}[n][m]$: $n \times m$ matrix defining remaining resource need.
$$\text{Need}[i][j] = \text{Max}[i][j] - \text{Allocation}[i][j]$$

Safety Criterion:
A state is safe if there exists a safe execution sequence $\langle P_0, P_1, \dots, P_{n-1} \rangle$ such that for each process $P_i$, the resources it still needs can be satisfied by:
$$\text{Need}_i \le \text{Available} + \sum_{k=0}^{i-1} \text{Allocation}_k$$
